# 网络与图传复测

## 2026-11-11 体感与断连复测

更新 STM32 V8.16 与基座 ESP-01S V4.11。STM32 的 PWM 上限仍为 30%，在偏离校准中心 30° 时饱和。任一轴超过 75° 停车。短时间越界回到 65° 内后须有连续有效帧，持续越界需要回中。串口接收出错立即撤销驱动，连续回中约 0.4 秒且至少收到 10 个新有效包后可重新起步。失联和主循环超时保护照常工作。

基座在关闭 HTTP 连接时直接交由 lwIP 发送剩余数据并完成关闭。网页控制台 http://192.168.4.1 会显示倾角超限、等待回中或等待有效输入。

首次复测将车架空固定。先只开遥控器，进入体感小车模式并放平遥控器。缓慢从约 30° 增至 60°，再回中，观察车轮输出是否持续。然后依次加开一个网页和 5 帧图传，比较是否复现卡顿。各组保存前后两份基座 /api/telemetry，记录测试时有没有关闭遥控器或主动断网。

| 读数 | 如何判断 |
| --- | --- |
| uptimeMs | 基座本次上电时间。测试中突然变小，先确认基座有无重启。 |
| maxUdpGapMs、skippedUdp | 基座接受的有效手持 UDP 包之间最长间隔和序号缺口。升高说明断档出现在基座收到包之前或处理收包时。 |
| maxForwardGapMs | 基座将手持指令写入串口的最长间隔。与 UDP 接收间隔比较，定位接收后到串口排队之间的断档。 |
| maxHttpPollUs | 基座单次 HTTP 处理最长用时，单位微秒。 |
| controlDiagnostics.uartRxFaults | 主控在小车模式内处理到的串口接收故障次数，包含串口硬件错误、接收队列溢出、超长行和 H1 校验失败。同一主循环间隔内的多个错误合并统计。 |
| controlDiagnostics.maxMotorServiceGapMs | 连续处于小车模式时，主控两次电机服务调用的最长间隔。 |
| controlDiagnostics.hold | 当前等待原因。1 为回中，2 为输入暂不可用，3 为倾角超限，4 为等待连续有效输入。 |

最长间隔从上电累计，包含主动断开。分组要单独比较，避免前一组的峰值盖住后续变化。主控诊断未收到或超时时显示 null。保留摄像头 /status 的 RSSI 和帧率便于对照图传。现场无线覆盖、供电、串口和实车长时表现仍需复测。

## 2026-11-10 图传更新

2026-11-10，基座 ESP-01S V4.10、ESP32-CAM V1.4、2D/3D 网页 V8.15。

- 基座每轮最多读 256 字节 HTTP 请求或写 512 字节响应。慢请求总寿命 450 ms，处理步骤之间继续转发遥控 UDP 和接收 STM32 串口。保留基座控制页、遥测、扫描、路线补传及旧路线驾驶接口的 410 响应。
- 网页分别显示基座不可达、基座在线但主控数据中断、手持端失联。控制模式下遥测轮询间隔调至约 160 ms，扫描模式保留原间隔。请求失败时逐步降低轮询频率。基座遥测中的数据年龄从收到 STM32 数据起算。
- 图传维持 320×240，正常档减小 JPEG 数据量，默认选 5 帧/秒。摄像头 RSSI 低于约 −75 dBm 或浏览器检测到收图慢时，启用省带宽档，约 3 帧/秒并进一步提高 JPEG 压缩。恢复有滞回。断流立即清空旧帧，再按间隔重试。视频面板的收图耗时由浏览器测得。

## 更新与验证

1. Arduino 上传 `project/ESP01S_Base_UDP/ESP01S_Base_UDP.ino` 对应的 ESP8266 基座程序，再上传 `project/ESP32CAM_Camera/ESP32CAM_Camera.ino` 对应的 AI Thinker ESP32-CAM 程序。两块板使用原工程和现有 Wi-Fi 配置。STM32、手持端及接线保持原样。
2. 打开新版 3D 或 2D 网页。只在一个窗口开视频，初次选 5 帧。若摄像头重新入网时 IP 变化，填串口打印的 Camera URL，或在能解析的设备上使用 `http://rover-camera.local/`。
3. 架空并固定车体，依次测试只开遥控、加一个网页、再开 5 帧图传。近距离运行一段时间后，再比较弱信号位置及恢复过程。
4. 若复现卡顿，保存基座 `http://192.168.4.1/api/telemetry` 和摄像头 `/status` 的读数。`maxForwardGapMs` 是基座上电后成功转发之间最大的间隔，含实际断连。`skippedUdp` 是同一已识别手持来源的已接收包序号缺口，不能直接当成电机延迟。比较连续运行前后增量与摄像头 RSSI、帧率、收图耗时。实车距离及墙体遮挡造成的无线覆盖问题仍需现场验证。
