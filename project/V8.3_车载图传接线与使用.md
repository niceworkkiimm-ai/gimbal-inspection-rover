## 通信方式

摄像头自己连接基座的 GimbalCtrl 热点。电脑/手机也连接这个热点：

- 体感控制仍走原有“手持 → 基座 ESP → STM32”链路。
- 距离、气体、路线仍由网页读取基座 192.168.4.1 的接口。
- 画面由网页直接请求摄像头 IP 的 /capture 接口，不经过 STM32 串口，也不通过基座 HTTP 转发。

注意：设备之间的无线流量仍需基座热点转发，仍共用 ESP8266 的无线带宽，不能理解为“完全不影响控制”。初始只用 QVGA 320×240、最高约 5 帧/秒，可在网页改成 3 帧/秒；网络差时实际帧率会更低，不保证低延迟。

基座当前默认最多 4 个 Wi-Fi 客户端。手持 + 摄像头 + 一台电脑 = 3 个，再加一部手机 = 4 个。打开多个浏览器页不增加 Wi-Fi 设备数，但会增加请求量。

## 先核对板子

商家手册写的是 ESP32-S3、16MB Flash、8MB PSRAM、标配 OV2640；引脚图标注 HW-679 V0.0.1。不是普通 ESP32 / AI Thinker ESP32-CAM。

本固件摄像头内部引脚逐项采用商家例程所选 CAMERA_MODEL_ESP32S3_EYE。这个宏表示此处采用的引脚映射，不是声称你买的是乐鑫官方 EYE 整机。

**供电待核实：手册图中的小板没有 USB 插座，只标了 VCC 和 3V3，文字又写“更换 5V 充电器供电”，没有明确 VCC 排针的输入电压或配套底板接法。不能仅凭 VCC 三个字就接 5V。请提供实物和烧录底板正反面，或让卖家确认 VCC 额定输入。**

## 新增接线（不改原来的线）

| 起点 | 接到哪里 | 说明 |
| --- | --- | --- |
| 摄像头排线 | 本摄像头板的摄像头插座 | 断电插拔、方向正确、锁扣压好 |
| 配套供电/烧录底板的 USB（如果有） | 已确认支持 5V 的 USB 电源/电脑接口 | 底板型号和插接方向先核对，不假定小板自带 USB |
| 摄像头 VCC 排针 | 暂不指定电压 | 等确认输入规格；不要接电机 Vin/电池原电压 |
| 摄像头与 STM32 | 不需要新增信号线 | 不接 UART、I2C、DCMI，不占新 GPIO |
| 摄像头与基座 ESP | 不需要信号线 | 使用 Wi-Fi；不从 ESP-01S 的 3.3V 供电脚给摄像头供电 |

独立供电、没有信号线时，不需要为 Wi-Fi 通信额外拉一根地线。若用 USB-TTL 烧录则必须共地。不要把电脑 USB 和外部电源输出未经隔离地直接并在一起。装车后应使用稳压电源和回流线路，避免与电机大电流共用细长供电线。

### 若使用 USB-TTL 烧录：已确定的信号线

下面仅是信号连接，不能据此认为供电已确认：

| USB-TTL / 操作 | 摄像头板 |
| --- | --- |
| TX，必须为 3.3V 逻辑 | RX / GPIO44 |
| RX | TX / GPIO43 |
| GND | GND |
| 进入下载模式 | GPIO0 接 GND，然后按板上 RST 或重新上电 |
| 下载完成后正常运行 | 断开 GPIO0 与 GND，再按一次 RST |
| RST | 不长期接地 |
| GPIO2 | 不需要照 ESP-01S 的接法拉高 |

这里 TX=GPIO43、RX=GPIO44 来自商家板图，不是 ESP8266 的 IO0/IO2。供电 5V 和串口 3.3V 逻辑是不同概念。

## 摄像头程序和 Arduino 设置

打开本工程内：

`ESP32S3_Camera/ESP32S3_Camera.ino`

不要烧进基座 ESP-01S，也不要打开 NodeMCU 的程序来给摄像头烧录。

电脑原来的 Arduino IDE 只有 ESP8266 核心。本次已在 D 盘独立验证环境中配置 Arduino-ESP32 **3.3.0**、官方 Xtensa 编译器和 SDK，下载包均按乐鑫官方索引的 SHA-256 校验，摄像头程序已经正式编译通过；没有改动原 Arduino IDE 设置。完整 Boards Manager 安装曾卡在其他芯片使用的 RISC-V 包，因此本次仅配置了 S3 编译必需部分。

如果以后想在原 Arduino IDE 内直接改代码并编译，仍需在 Boards Manager 安装 **esp32 by Espressif Systems**（3.3.0）。如果只是烧录这次版本，可使用已编译的合并固件，不必先重新下载整套开发环境。编译通过不代表已经烧录或实物图传测试通过。

Arduino IDE 的英文菜单：

| 设置 | 选择 |
| --- | --- |
| Board | ESP32S3 Dev Module |
| Flash Size | 16MB (128Mb) |
| PSRAM | OPI PSRAM（按资料8MB规格；实物标识不同先核对） |
| Partition Scheme | Huge APP (3MB No OTA/1MB SPIFFS)；实际分区由源码目录 partitions.csv 覆盖 |
| Upload Speed | 115200，先用较低速率 |
| CPU Frequency | 240MHz (WiFi) |
| Flash Mode | DIO 80MHz（Arduino-ESP32 3.3.0 的实际菜单项） |
| Flash Frequency | 本核心该板没有单独的频率菜单；商家旧下载截图中的40MHz不是当前IDE菜单项 |
| USB CDC On Boot | Disabled（本说明按 TX43/RX44 的 UART 烧录/日志） |
| Port | 实际 USB-TTL 或配套烧录器的 COM 口 |
| Serial Monitor | 115200 baud |

如果实物实际上通过 S3 原生 USB 下载，USB CDC 设置和日志接口可能不同，需要先看板子，不能直接照 UART 设置猜。源码文件夹自带 partitions.csv，给程序保留 3MB 空间，不启用 OTA；保留标准 otadata 区域以兼容 Arduino 烧录布局，不需要复制商家带人脸识别的分区表或 camera_index.h。上表设置仍需在实物上验证启动和摄像头工作，不等同于已经确认全部硬件参数。

热点和安装方向集中在 CameraConfig.h：

- 默认热点：GimbalCtrl，密码：<LOCAL_WIFI_PASSWORD>，与你当前基座一致。
- 固件只做 Wi-Fi 客户端，不创建新的 192.168.4.1 热点，避免与基座混淆。
- IP 由基座 DHCP 分配，不假定 .2 或 .3 一定空闲。
- CAMERA_VFLIP=1 与商家例程一致，CAMERA_HMIRROR=0 不默认左右镜像。装车后用手在镜头左右/上下移动验证，再调整，不改小车转向映射。
- 板上 LED、WS2812、TF 卡、其他按键不使用。此版不带录音、录像、识别或夜视。

## 联调顺序

已编译合并固件位于：

`ESP32S3_Camera/ESP32S3_Camera_V1.0_merged.bin`

这是包含启动程序、分区表和应用的合并镜像。若使用支持 ESP32-S3 的烧录工具，应从 **0x000000** 写入；不是把单独的应用 bin 当作地址0固件。选择芯片 ESP32-S3，先用 115200 波特率；供电、下载模式和实际 COM 口确认后再操作。**不能烧进 STM32、ESP-01S 或 NodeMCU。** 编译缓存中的 .elf/.map 和16MB填充镜像不需要复制到原工程，用户用这一个合并文件即可。

1. 固件已经编译通过。先确认供电和接线，再给新摄像头烧录；不要重烧原有三个控制设备。
2. 打开基座电源，让它产生 GimbalCtrl 热点；先不让电机转动。
3. 摄像头上电/复位，Serial Monitor 设置 115200。应看到：
   - Camera initialized ...
   - WiFi connected. Camera URL: http://实际IP/
   - Camera ready: YES; HTTP ready: YES
4. 电脑连接 GimbalCtrl。没有互联网是正常现象，不代表没连上热点。
5. 先在浏览器打开串口给出的 Camera URL，点击“开启画面”。这个独立页面由摄像头提供，不用另建后台服务器。
6. 独立页面画面正常后，先“关闭画面”，等 3 秒，再打开本工程原来的 2D 或 3D 网页，确认显示 V8.3。
7. 在顶部“车载画面”里填摄像头地址，点击“开启画面”。默认 rover-camera.local 只是方便尝试的域名；解析失败就填串口打印的 IP。
8. 点“悬浮”可一边滚动看路线，一边看画面；“嵌回页面”恢复。“放大画面”受手机浏览器支持情况限制。
9. 先用架空/固定的小车验证画面左右方向及遥控响应；然后在有人看护的空地低速测试。比较视频关闭和开启时的遥控响应，卡顿就先关视频、排查供电和信号，再降为 3 帧/秒。

如果发到手机上，网页要连同 camera-panel.js 及原有所有依赖文件一起提供，不能只发 HTML。手机聊天软件的文件预览不一定允许运行完整网页；优先用实际浏览器打开。跨域/局域网访问被浏览器拦截时，允许其访问本地网络；不要关闭整个浏览器的安全保护。可以先用摄像头自己的 Camera URL 单独查看，绕过本地文件的跨域限制。

## 为什么有些情况下会关闭画面

- 默认不开视频，不后台占用带宽。
- 同一摄像头同一时间只接受一个查看者。另一窗口会提示“已有其他窗口收图”；关掉原窗口，等 3 秒再开。
- 切换到后台/其他页面后自动关闭，返回需要重新开启。
- 单次收图 1.2 秒超时；收到的帧太旧、重复、损坏，或者收图耗时超过 1 秒，不显示成实时画面。
- 超过 1 秒没有新图就清空旧画面并提示。主网页最多重试 3 次，失败后需手动开启；不会积压视频请求。
- “收图 xx ms”只是本次 HTTP 收取和解码的耗时，不是从镜头曝光到屏幕的总延迟，更不是遥控延迟。

本功能不新增自动停车指令，也不修改原有运动保护。**看到画面中断/过期必须主动停车，不能凭最后一帧继续驾驶。** 低帧率图传仅作近距离低速辅助，不适合作为无人看护或真实矿井安全作业的可靠视觉保障。

## 排错速查

| 现象 | 优先检查 |
| --- | --- |
| PSRAM not found | Board 是否为 ESP32S3 Dev Module、PSRAM 是否 OPI、实物是否与8MB资料一致 |
| camera init 失败 | 断电检查排线/摄像头型号、电源；不能把普通 ESP32-CAM 引脚套过来 |
| 等待 GimbalCtrl | 热点电源、密码、2.4GHz、连接设备数量不超过4 |
| 有 IP 但画面失败 | 先打开摄像头 IP/status，看 cameraReady 和 cameraError；查串口 |
| 填 .1 被拒绝 | 192.168.4.1 属于基座，填摄像头串口 Camera URL |
| mDNS 域名打不开 | 改用实际 IP，IP 可能在重连后改变 |
| 主网页提示旧固件 | 本功能需要 ESP32S3_Camera V1.0，不能只烧商家原例程 |
| 单独画面能看，2D/3D 不能看 | 浏览器局域网权限、跨域限制、camera-panel.js 是否与 HTML 同目录 |
| 开视频后控制变卡 | 关视频对比，限制只一个查看窗口、降到3fps、检查信号和电源 |

摄像头服务没有另加账号密码，只适用于受控的私人热点；能接入热点的人可能查看画面。不要把服务端口暴露到公网。若以后改热点密码，需要同步更新基座、手持、摄像头，不能只改一个。
