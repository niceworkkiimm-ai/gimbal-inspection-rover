## 编码器接线

四个轮子各取 A/B 两根信号线，一共 8 根接到 STM32。使用 A 相上升沿外部中断计数，B 相判断方向，不占用新的定时器。

| 驱动板编码器信号 | STM32 | 轮子 |
| --- | --- | --- |
| E1A | PE2 / EXTI2 | 1 左前 |
| E1B | PF8 | 1 左前 |
| E2A | PE3 / EXTI3 | 2 右前 |
| E2B | PF11 | 2 右前 |
| E3A | PF6 / EXTI6 | 3 左后 |
| E3B | PD6 | 3 左后 |
| E4A | PF7 / EXTI7 | 4 右后 |
| E4B | PD7 | 4 右后 |
| 驱动板 GND | STM32 GND | 整车共地 |
| 电机六芯插头 | 保持接驱动板对应接口 | 动力线和编码器供电继续由原接口连接 |
| 编码器 VCC | 若驱动板已供电，不再接另一组电源 | 不把外部 3.3V 并到驱动板电源输出 |
| A/B 电平 | 本方案按 3.3V 设计 | 驱动板若输出 5V，先加电平转换再接上述 GPIO |
| PF11 / PD6 / PD7 | 不同时接旧触摸或摄像头模块 | 已核对现有工程未使用 |

其余屏幕、灯带、超声波、气体、语音、舵机、手持端和电机驱动接线保留，完整表在 User/main.c 开头。PD3 仍不接。

## 第一次使用

1. 先核实驱动板编码器 A/B 输出电平，再接 8 根信号线和公共地。
2. 烧录 STM32 V6.5 与基座 ESP V4.4。
3. 电脑连 GimbalCtrl 热点，打开本目录的 2D 或 3D 网页。
4. 找到页面下方“巡检行驶轨迹”。即使未完成标定，也能看到四轮原始计数。
5. 展开“轨迹标定与轮子方向”。逐一转动车轮，方向按“该轮这样转会让车前进”判断：原始计数增加选 +1，减少选 −1。四个轮子分别设置。
6. 核对标准 X 型麦轮安装：俯视滚子轴线前排为 ＼ ／，后排为 ／ ＼。别只按轮子颜色判断。
7. 确认尺寸和每圈计数，勾选已核对方向，点击“保存标定并重新开始”。
8. 页面从下一包数据开始记录当前位置为起点，开始时车头方向为图中上方。先低速直走、倒退和转弯观察。

“确认轮向”只影响网页是否换算米数，不会给电机上锁，也不会发送任何控制指令。

## 页面行为

| 功能 | 行为 |
| --- | --- |
| 行驶轨迹 | 独立的平面路线图，绿色箭头表示当前位置及朝向 |
| 累计路程 | 按车体中心位移累计；倒退也累加，纯原地旋转不把轮子转动量当成车体行程 |
| 距起点 | 当前估算位置到起点的直线距离 |
| 速度与轮速 | 使用主控时间戳计算，断联后显示横线 |
| 原始计数 | 来自各轮编码器，未应用轮向符号；每轮转速已应用标定符号 |
| 查看全程 / 跟随 / 缩放 / 平移 | 调整轨迹视野，不改变原雷达的距离比例 |
| 重新开始 | 仅重置当前页面路线和里程，从下一包重新设起点 |
| 导出轨迹 | 下载 CSV，包含标定参数、位置、方向、路程及分段标记 |
| 长路线 | 不按时间删除；超过约 10000 绘制点时简化历史，累计路程保持 |
| 数据中断 | 保留旧路线，缺口分段；缺失段只能按累计轮数粗估，路程可能低估 |
| 主控 / 基座重启 | 新数据重新建立计数基线，旧新路线不连接，提示重新设起点 |
| 网页刷新 / 关闭 | 路线只属于当前打开的页面会话，结束前应导出；标定参数尽量保存在浏览器 |
| 2D 与 3D 同时打开 | 各自从本页开始时记录，清空和导出互相独立 |

3D 页面里的新行驶轨迹仍是地面二维路径。原超声波 3D 点云继续以云台为原点；本版没有把障碍物点云融合成整个矿道的全局地图。

## 计算与传输

STM32 持续累计四轮计数，每约 80ms 发送 E1 帧，包含序号、主控毫秒时间、四个累计计数及 CRC16。计数正负通过 uint32 回绕传送，网页按有符号差值还原。

基座校验后保留最近 16 帧（正常约 1.3 秒），随原 /api/telemetry 返回 odometry 字段。两个页面沿用各自现有的轮询，不另开一条轮询。

网页根据轮径、每圈计数、轮距、轴距及各轮符号计算标准 X 型麦轮里程计。重复样本不重复累计；短暂漏收 HTTP 包可从缓存补齐。超过缓存或串口丢帧时，累计轮数仍可恢复，但期间具体弯曲路径不能还原，界面将缺口分段。没有真实参数/轮向确认时不会显示假米数。

不使用手持 MPU 的角度充当车头方向。轮子打滑、离地空转、地面不平、机械误差都会让路线漂移；本功能是编码器估算轨迹，不是绝对定位或防滑检测。
