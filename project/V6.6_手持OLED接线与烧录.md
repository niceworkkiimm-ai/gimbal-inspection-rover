# V6.6 手持 OLED 显示

日期：2026-09-09。手持 NodeMCU 固件 V1.2。

## 本次烧录哪一个

只需给手持 NodeMCU V3 CH340G 烧录本目录内的 `NodeMCU_Handheld_MPU_Car/NodeMCU_Handheld_MPU_Car.ino`。

STM32 V6.5、基座 ESP V4.4 可以继续使用；网页不用更新。本次 User/main.c 只更新 V6.6 版本/接线说明，去除注释后的 STM32 源码与修改前一致。

不要烧录旧的 ESP01S_Handheld_MPU_UDP。不要把 INO 单独复制出去：同文件夹中的 HandheldProtocol.h、HandheldOled.h、HandheldOled.cpp、HandheldOledFont.h 必须一起保留。无需另外安装 OLED 库，使用现有 ESP8266 core 3.1.2 自带的 Wire。

## 屏幕型号前提

本次用户尚未提供屏幕型号，因此按常见 **SSD1306、128×64、4针 I2C、支持3.3V供电** 编写。地址自动尝试 0x3C 和 0x3D；地址响应不能识别控制器型号。

SH1106、128×32、SPI 等屏幕不能据此宣称兼容。若型号不同或显示偏移，请提供屏幕型号/正反面照片，再匹配驱动，而不是反复换线。

## 手持完整接线

先断电接线，按照模块丝印，不按排针左右顺序猜。

| 部件引脚 | NodeMCU 接口 / 要求 |
| --- | --- |
| OLED VCC | 3V3，屏幕须支持3.3V |
| OLED GND | GND |
| OLED SCL | D1 / GPIO5，与 MPU6050 SCL 并接 |
| OLED SDA | D2 / GPIO4，与 MPU6050 SDA 并接 |
| MPU6050 VCC | 3V3 |
| MPU6050 GND、AD0 | GND |
| MPU6050 SCL | D1 / GPIO5 |
| MPU6050 SDA | D2 / GPIO4 |
| MPU6050 INT、XDA、XCL | 不接 |
| 原切换按钮 | 两端分别接 D5 / GPIO14 和 GND，内部上拉 |
| 板载状态灯 | D4 / GPIO2，程序继续使用，无需外接 |
| USB 烧录/供电 | NodeMCU 板载 USB 接电脑/稳定5V USB电源 |
| 不用 USB 时的供电 | 稳定5V正极接 VIN，负极接 GND，不与 USB 同时供电 |
| EN、RST | 保留开发板原有电路，无需外接 |
| GPIO0、GPIO2 | 正常运行不要接地；USB自动下载不需要手动拉线 |
| SCL/SDA 上拉电压 | 只能到3.3V，不能上拉到5V |

如果模块都自带上拉，不要额外随意并联很小的上拉电阻。共用 I2C 线尽量短、连接牢靠。拔下未供电屏幕或错误接线可能拖低总线，同时影响 MPU6050。

## Arduino IDE 操作

1. USB 数据线连接手持 NodeMCU；MPU 和 OLED 保持上述接线。
2. 打开 `NodeMCU_Handheld_MPU_Car.ino`，不要打开基座或旧ESP-01S手持程序。
3. `Tools > Board > esp8266 > NodeMCU 1.0 (ESP-12E Module)`；这是 NodeMCU V3 常用板型，不选 Generic ESP8266 Module。
4. `Tools > Upload Speed > 115200`，`CPU Frequency > 80 MHz`，`Port` 选择 NodeMCU 对应 COM 口。其他选项保留原来能成功烧录的 NodeMCU 设置。
5. 点击 `Verify`，成功后点击 `Upload`。本次已在电脑编译通过，但没有代为烧录。
6. 上电/复位时保持手持静止，等 MPU 原有校准结束（约1～2秒）。OLED 在主循环运行后初始化、填充画面才点亮，不是背光式显示屏。
7. 短按并松开按钮，检查“云台模式”与“小车模式”切换；长按0.8秒显示“停车请求”。松开保持该请求，再短按返回云台。

## 显示内容

| 内容 | 含义 |
| --- | --- |
| 云台模式 / 小车模式 | 手持端当前选择的请求模式，不是基座执行确认 |
| 停车请求 | 长按进入的软件停车请求，不能替代直接切断电机电源 |
| WiFi 已连接 / 未连接 | 是否关联基座热点，不证明 STM32 或电机已收到数据 |
| 负数及信号格 | WiFi RSSI，单位dBm，例如 −59；越接近0通常信号越强 |
| R、P | MPU6050 滤波后的 Roll、Pitch，单位度；无新有效读数时显示横线 |
| 手持就绪 | 手持端满足现有输入有效条件；STM32可能仍在等待回中或其他状态 |
| 等待姿态稳定 | 正在等待原有100ms有效输入稳定时间，不新增控制门槛 |
| 松开切换模式 | 原有按钮已确认按下，短按松开后切换 |
| MPU异常请检查 / 姿态数据异常 | 传感器初始化或读取异常，不用0°代替未知值 |

没有加入电量、气体、距离、车速等手持端没有收到的数据，也没有新增基座回传协议。

## 实时性与验证

- 原有20ms控制周期、H1报文、35ms消抖、0.8秒长按、MPU滤波和重连逻辑保留。
- 显示数值约每200ms生成一帧，模式/连接/有效性变化优先生成；只更新改变的16字节块。
- 仅在距下次控制采样至少6ms的空隙进行一次 I2C 事务；不一次发送整屏1024字节。
- MPU 的总线速率仍为100kHz，时钟拉伸等待仍为1500us。OLED事务暂用15us/位，结束立即恢复。ESP8266 core 的限制是每位而非整笔事务，不能把1500us错误当作全局超时。
- 屏幕无响应后退出显示刷新，约5秒尝试重新探测。SDA/SCL已经被拉低时不启动OLED事务。共用线路真正短路时仍会影响MPU，软件无法物理隔离。
- NodeMCU V1.2 使用 ESP8266 core 3.1.2 / nodemcuv2 编译通过；无新增显示库依赖。
- 原按键、异常计数与基座H1转发回归通过；真实手持源码在仿真中验证屏幕有/无、切换、长按、断网、MPU失败及约50Hz发送。
- OLED初始清屏、0x3C/0x3D、断开/重试、数据分块、时间回绕、中文字符覆盖及像素预览检查通过。
- 尚未在真实OLED上验证型号、显示方向、上拉、电源、总线波形及实际发送抖动。模拟通过不等于实物已验收。
