## 接线（与 V5.2 一样，没有更换引脚）

断电接线；完整整机接线见 `User/main.c` 开头注释。

| 气体模块引脚 | 接到哪里 |
| --- | --- |
| + | 稳定 5V，模块要求 4.5–5.5V |
| - | STM32 GND，整机共地 |
| R / RX | PA2，USART2_TX |
| T / TX | PA3，USART2_RX |

模块串口是 3.3V TTL，9600、8 数据位、无校验、1 停止位。5V 供电不代表串口信号是 5V。
默认轮询地址 1–4；实际气体名称按返回的类型识别，未知类型不会硬标成 CH4/O2/CO/H2S。
气体模块不要接到 PA9/PA10（那是基座 ESP 使用的 USART1）。

基座 ESP：TX → PA10；RX ← PA9；稳定 3.3V 供电，共地。完整屏幕、舵机、语音、灯带和手持端接线都保留在主函数开头。

## 修复内容

1. 根据四合一模块手册修正寄存器 0 的单位、小数位与浓度扩展位：
   - 单位码 0/2/4/6/8：ppm / %LEL / %VOL / mg/m3 / ppb；
   - 小数位编码 0/4/8/12：0/1/2/3 位；
   - 浓度支持 18 位，不再截断到 65535；
   - 状态读取寄存器 5 低字节，气体类型读取寄存器 8 高字节。
2. 在线不等于正常：CRC 正确的故障响应仍显示“传感器故障”，浓度为“--”；报警数值可显示，但标红。
3. 状态 0 显示预热；状态 4 预警；5/6/11/12 报警；8 超量程且不把越限原始数当有效浓度；未知/故障状态不会显示正常。
4. 串口发送采用固定容量、中断驱动；USART1 按完整行入队，队满丢整帧，发送停滞后清队列并补换行重新同步。USART2 无响应会超时退出，不无限等待。
5. 气体每 200ms 查询一个通道，四通道约 0.8s 一轮；每次响应超时 120ms，单通道样本 1.5s 无更新失效。调度时间会受既有主循环工作影响。
6. ESP 气体遥测 3s 无更新失效；网页请求异常或模块离线会清除有效数值。支持重复帧过滤、序号回绕和重新连接。
7. 温湿度寄存器在手册中的说明与示例矛盾：本版不臆测换算，API 中 temperature/humidity 为 null，页面不展示。需要厂家提供确认的编码/样本后再加。
8. 原有 2D/3D 距离量程、近距离放大比例、方向、点云数量与采点逻辑保持不变。旧 web-dashboard 同步修复气体显示、请求超时和演示/设备切换。
9. 气体报警这里只做网页显示，**没有**擅自改变原来按障碍距离工作的蜂鸣器、语音和灯带。

## G2 遥测格式

STM32 → 基座 ESP，USART1 115200：

`G2,序号,通道1到4,模块在线0或1,浓度可用0或1,18位原始浓度,单位码,小数位数,状态码,气体类型\n`

例如 `G2,1,2,1,1,209,4,1,1,67` 表示氧气 20.9 %VOL、正常。

HTTP 接口仍为 `http://192.168.4.1/api/telemetry`。
气体对象增加实际 unit、中文 statusText、severity；online 表示新鲜模块响应，valid 表示浓度可用于显示，**不代表环境安全**。
normal 也只是“模块报告正常”，不代表经过安全认证的作业许可。

## 上电检查

1. 两端固件一起更新，电脑连接 GimbalCtrl 热点，打开控制页和新版本 2D/3D 文件。
2. 模块上电后按手册建议等待约 180s 稳定。网页“预热中”来自模块状态，并非独立计时的 180s 稳定证明。
3. 核对气体名称和单位；例如氧气是 %VOL，不要把 %LEL 当成体积百分比。不要靠单一参考值判断所有通道都已经标定。
4. 不拆电源的情况下安全断开模块信号线，确认气体卡片变成无新数据且不保留正常数值；再接回观察恢复。
5. 断开电脑 Wi-Fi，确认页面浓度变成“--”；重新连接后自动恢复。
6. 检查手持控制、自动扫描、屏幕、超声波、灯带与语音仍正常。
7. 不要用真实有毒/易燃气体临时造测试环境。定量精度、报警阈值与恢复时间需用规范的标气及合适条件验证；本项目原型不能替代矿用认证安全检测仪。
