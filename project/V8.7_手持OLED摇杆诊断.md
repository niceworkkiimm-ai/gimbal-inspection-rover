# V8.7：手持端 OLED 摇杆诊断（2026-09-15）

手持程序 V1.4。只需用 Arduino IDE 重烧 `NodeMCU_Handheld_MPU_Car/NodeMCU_Handheld_MPU_Car.ino`，整个同名文件夹中的 .h/.cpp 必须一起保留。开发板选择 **NodeMCU 1.0 (ESP-12E Module)**，Upload Speed 115200，选择实际存在的手持串口。

STM32 执行代码仍 V8.2，基座 ESP V4.8、网页 V8.5 和摄像头 V1.2 均未改变，不需重烧。本次 `User/main.c` 只更新版本与接线注释。

## 怎么看屏幕

切到“摇杆小车”即可看到诊断页，不新增按钮操作。右上角有 WiFi 表示手持已连接热点，横线表示未连接；这不是 STM32 的接收确认。

- **V1.4**：确认运行的是本次固件。
- **E编号 + 中文提示**：当前采样/校准状态；E00 时根据无线/按键/回中状态显示等待连接、松开按键、请松手回中或手持就绪。E00 不表示车端已经允许行驶。
- **X/Y**：最后一次完整两轴转换的 ADC 原始值，不是百分比、角度或速度。±4.096V 配置下每计数约 0.125mV，3.3V 供电的普通摇杆松手通常在 13200 左右。没有完整读数时显示横线，不把未读到的值伪装成 0。
- **新值**：完整采样当前有效，仍可能校准未完成；**无效**：最后读数已经失效/过期或越界，仅供排查，绝不用于控制；**无值**：尚未获得完整两轴读数。
- **C**：中点校准进度，0～100；100 表示已经学到中点，不代表通信/控制当前有效。采样故障后保留已经学到的中点，但控制仍需新数据并重新回中。
- **L**：最近一次采样故障的编号，恢复后也保留到手持复位，00 表示尚无采样故障。仅是历史，不一定是当前故障。
- **N**：累计采样故障次数，手持复位清零。中点超范围、抖动、等待首次采样等不是 I2C 采样故障，所以 N 可以为 0。
- **S/W**：L 对应的上次故障阶段及 Wire 返回码，不是新增加的引脚。S=0/3 发起 X/Y 转换，1/4 等待转换，2/5 读 X/Y，S=0 也用于完整读数越界。W=2 是地址未应答，W=3 为写入数据未应答，W=4 为总线其他错误；W=0 不代表整个采样成功，仍可能短读、超时或配置错误。

## 错误码

| 编号 | 提示 | 排查方向 |
| --- | --- | --- |
| E00 | 手持就绪/请松手回中等 | 采样和校准正常，继续看无线、按键及回中提示；不是车端执行反馈 |
| E01 | 等待首次采样 | 刚启动，尚无完整数据；持续存在需查看调度/通信 |
| E02 | ADS无响应 | 固定地址 0x48 未应答；核对 ADDR→GND、供电、SDA/SCL 和接触；不能直接断言模块损坏 |
| E03 | 写入失败 | 启动转换的配置写入失败，看 W 返回码和接线 |
| E04 | 读取失败 | 寄存器指针发送失败或没有读满两字节，看 W；可能接触、供电或总线问题 |
| E05 | 总线被拉低 | SDA/SCL 空闲时为低；共用总线短路/拉低也可能让 OLED 无法显示本错误 |
| E06 | 总线传输超时 | 单次寄存器操作用时达到 6ms；需查总线和实际调度延迟 |
| E07 | 配置读回异常 | 读回的 MUX/PGA/速率等与写入值不符；查芯片型号、供电及通信可靠性 |
| E08 | 转换等待超时 | 等待一次转换超过 30ms；芯片未完成或软件没有及时服务 |
| E09 | 两轴采样超时 | X/Y 整组超过 50ms；查服务时序、无线/共享总线影响 |
| E10 | 原始数据越界 | 读数低于 -16 或高于 27200；不是允许输入高电压，信号仍不得超过 3.3V 供电范围 |
| E11 | 采样数据过期 | 超过 100ms 没有新的有效完整数据 |
| E12 | 中点超出范围 | 初次校准时至少一轴不在 11200～15200（约 1.40～1.90V）；松手并看 X/Y，不盲目改保护 |
| E13 | 中点读数不稳 | 初次校准稳定窗口被超过 160 计数（约 20mV）的波动打断；提示保留到稳定校准成功或出现别的问题 |
| E14 | 等待中点校准 | 数据处于合理区间，等待至少 400ms 且 12 组稳定数据，C 显示进度 |
| E15 | 采样未获调度 | 超过 100ms 没有获得至少 6ms 的服务空隙；属于调度诊断，不等同于模块无响应。屏幕也可能暂时无机会刷新；两组采样之间发生的服务中断会在恢复时保留 L15/N 记录，组内中断由原有 E09 记录 |

所有原采样条件、400ms/12组校准、20mV稳定门槛、8%回中死区、三模式切换和 H1 协议保持不变。不自动换 ADC 地址，不增加全总线扫描，不自动放宽校准。L/S/W/N 只记录已有采样过程，不新增 I2C 事务。

## 怎么排查

先固定车架、四轮架空；手持水平静止、摇杆松开约 2 秒，再短按切入摇杆小车。拍下包含 V1.4、E、X/Y、C、L/N 的整屏照片。若数字/状态有变化，可录 5～10 秒视频。不需要先修电脑串口来查看这页。

如果出现 E12/E13，先看原始值和 C，而不是反复重烧 STM32。若 E02，重点核对 ADS1115 ADDR、并接线与接触。若 E06/E08/E09/E15，记录 L/S/W/N 辅助区分时序问题。只有查明实物情况后才调整算法参数。

**限制：** OLED 与 ADS/MPU 共用 SDA/SCL。持续总线短路或拉低时，OLED 可能冻结，旧画面不能证明实时状态；软件不能让已无法通信的屏幕可靠显示新错误。那时需断电排查接线、分支或借助万用表/逻辑分析仪。原始模拟线断开后如果恰好呈现合理电压，软件也不能保证识别为断线。

固件编译/离线模拟不等同于实物验收；实际故障原因要以更新后的屏幕和硬件检查为准。
