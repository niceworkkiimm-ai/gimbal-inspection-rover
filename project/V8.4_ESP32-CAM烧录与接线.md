## 先认准实物与程序

你的实物是 **ESP32-CAM（模块金属罩写 ESP-32S）**，烧录底板是 **ESP32-CAM-MB，CH340C，Micro-USB**。这与先前提供的 ESP32-S3CAM 资料不是同一块硬件。

烧录错误 “This chip is ESP32, not ESP32-S3” 正是芯片型号不匹配。既要换开发板选项，也要换摄像头引脚配置；只改菜单不够。不得用强制忽略芯片型号的方式烧录。

本次只打开：**ESP32CAM_Camera/ESP32CAM_Camera.ino**。同文件夹 CameraConfig.h、CameraHome.h 不要拆开。
旧 ESP32S3_Camera 文件夹及旧 S3 合并 bin 保留作历史，当前板子不要使用。

## 使用烧录底板：最少接线

| 起点 | 接到哪里 |
| --- | --- |
| 摄像头排线 | 摄像头板插座；断电时插好并锁紧 |
| 摄像头板两排针 | ESP32-CAM-MB 配套底板；按标识对齐，不能反插、错位 |
| 底板 Micro-USB | 电脑 USB 数据口；必须用数据线，不是仅充电线 |
| 外置 USB-TTL | 使用这个底板时不需要 |
| STM32 / 基座 ESP 的 TX、RX | 都不用接摄像头 |
| GPIO2 | 不要另接高电平 |
| GPIO0 / 底板 IO0 | 仅进入下载时拉低；运行时松开，不接 GND |
| RST | 瞬时按下复位，不长期接地 |

供电和串口逻辑电压不是一回事：底板 USB 是5V供电，ESP32串口信号是3.3V。

如果脱离底板装车：

| 电源 | 摄像头板 |
| --- | --- |
| 稳定的 5V 输出（建议额定至少 1A 留余量） | **明确标注 5V** 的针脚 |
| 电源 GND | GND |
| 旁边带 3V3/5V 选择焊盘的 VCC 脚 | 本方案不使用 |
| 3V3 脚 | 不接 5V |
| 电池原电压 / 电机 Vin | 不直接接摄像头 |
| USB 与外部 5V | 二选一，不同时供电 |

不要从 ESP-01S 的3.3V引脚或弱供电 USB-TTL 的3.3V输出给摄像头供电。与电机共用电池时用稳定降压支路，避开细长的大电流回流线。独立电源、没有信号线的两个模块不需要为 Wi-Fi 额外共地。

备用 USB-TTL 仅在不用 MB 底板时参考：3.3V逻辑 TX → U0R/GPIO3；RX ← U0T/GPIO1；GND → GND；供电仍按上表。不是 S3 的 GPIO43/44。

## Arduino IDE 设置

已安装 **esp32 by Espressif Systems 3.3.11**，不用重新下载。打开新 ino 后：

| 英文菜单 | 选择 |
| --- | --- |
| Tools → Board → esp32 | **AI Thinker ESP32-CAM** |
| Tools → CPU Frequency | **240MHz (WiFi/BT)** |
| Tools → Flash Mode | **DIO** |
| Tools → Flash Frequency | **40MHz** |
| Tools → Partition Scheme | **Huge APP (3MB No OTA/1MB SPIFFS)** |
| Tools → Core Debug Level | None |
| Tools → Erase All Flash Before Sketch Upload | Disabled |
| Tools → Port | 插入 CH340 底板后新增的 COM 口 |
| Serial Monitor | **115200 baud** |

注意：3.3.11 的 AI Thinker 配置默认按4MB Flash构建并启用PSRAM，没有独立的 Flash Size、PSRAM、USB CDC On Boot、Upload Speed 菜单。**没有这些菜单是正常的**，不要为了找它们换回 S3。此板配置的上传速度固定默认460800；遇到传输中断先检查数据线和供电，必要时另做低速上传，不是重新安装开发包。上面的115200是查看日志的波特率，与上传速度分开。

4MB是官方开发板配置，不是已经对你的板子做过容量检测。运行时会打印芯片型号、Flash和PSRAM实测容量；照片无法确认所有克隆板的存储配置。

## 上传和验证

1. 摄像头插好底板，用 USB 数据线连接电脑，选对 Board、Port 和上述选项。
2. 先点 **Verify** 等编译通过。
3. 按住底板 **IO0**，按一下 **RST** 再松开 RST，随后松开 IO0。芯片已在下载模式。
4. 点 **Upload**。如仍停在 Connecting，保持 USB 连接，再做一次“按住 IO0 → 按一下 RST → 松开 IO0”。
5. 等待上传到100%且没有报错；松开 IO0，打开 **Serial Monitor**，选115200，按一下 **RST** 启动程序。
6. 日志开头应包含 **Rover camera V1.1 / ESP32-CAM**。先开基座，让它产生 **GimbalCtrl** 热点。
7. 需要看到 **Camera initialized**、**Camera ready: YES**、**HTTP ready: YES**，以及 **Camera URL: http://实际IP/**。程序只连接热点，不另建热点。
8. 电脑连接 GimbalCtrl，浏览器打开日志给出的 Camera URL，点“开启画面”。先在停车状态检查实物出图。
9. 关闭独立查看页面的画面，等3秒；再打开原来的2D或3D网页，在“车载画面”填这个摄像头地址，点击开启。同一时间只在一个窗口收图。

不是192.168.4.1：那个地址是基座。摄像头由DHCP分配IP，不能假定永远是.2或.3；重连后可能变化。rover-camera.local 只作便利域名，不支持解析时使用实际IP。

GPIO0同时是摄像头时钟引脚，烧录后若还短接到GND，程序无法正常运行。IO0不要保持按下；复位后进入下载日志而不是V1.1日志时先检查这一项。

## 与网页的兼容性、限制

- 新固件修订号为1.1，但 HTTP **X-Camera-Version** 接口版本仍为1.0，兼容现有两页与独立查看器；不需要修改网页。
- camera-panel.js仅同步修正旧S3名称提示和“图传接口1.0”文案；两份HTML、收图机制及控制逻辑不变，刷新页面即可。
- 图像直接由浏览器请求摄像头，不走STM32串口或基座HTTP，但仍共用ESP8266热点的无线带宽。
- 320×240 JPEG，最高约5帧/秒；网页可降至3帧/秒。默认关闭、单查看者、防积压、过期画面清空等机制保持。
- 基座当前最多4个Wi-Fi客户端。手持、摄像头、电脑共3个；再加手机为4个。
- 本版不使用TF卡、闪光灯、音频、识别或自动停车；看到断流、过期或遥控变卡请主动停车。
- 对着镜头上下/左右移动手检查安装方向；需要翻转时仅改CameraConfig.h的CAMERA_VFLIP/CAMERA_HMIRROR后重烧摄像头，不改小车方向。
- 服务无独立登录鉴权，只适合受控私人热点，禁止开放公网端口。

## 常见问题

| 现象 | 检查 |
| --- | --- |
| This chip is ESP32, not ESP32-S3 | Board仍选了S3或正在上传旧S3固件；改用新目录与AI Thinker |
| 只有Connecting | 选对新增COM口；关闭占用串口的窗口；按IO0/RST进入下载；检查数据线 |
| 下载完成后没运行 | IO0松开/取消GPIO0接地，再按RST |
| PSRAM not found | AI Thinker配置、供电、板子PSRAM硬件；不要选OPI |
| camera init失败 | 先断电，检查排线锁扣/方向、摄像头本体、5V供电；拍完整串口日志 |
| Camera ready:NO但Wi-Fi已连接 | Wi-Fi成功不等于摄像头成功，查看/status和初始化错误码 |
| 一直等GimbalCtrl | 基座开机、热点密码、距离、4个客户端上限 |
| 有IP但两页没图 | 先打开独立Camera URL，再检查网页局域网访问权限和camera-panel.js |
| 开视频后控制卡顿 | 停车，关视频对比，改3帧/秒，检查供电和信号 |

## 验证记录

已通过 Arduino-ESP32 3.3.11 / AI Thinker ESP32-CAM 正式编译、链接，未报告警告或错误。程序占用1,057,957字节，全局变量59,832字节；运行时内存占用需实测。镜像检查目标芯片为ESP32（Chip ID 0），4MB/DIO/40MHz，启动镜像和应用校验均有效。编译产物和测试日志保存在D盘缓存，用户直接用Arduino上传本目录ino即可。

已逐项核对17个摄像头/闪光灯引脚与官方AI Thinker映射一致。STM32从首个#include起的全部代码、摄像头段之后的全部原接线注释、两份网页HTML完全不变；共用视频窗口仅改型号提示与接口文案。

两页电脑/手机尺寸及摄像头独立页面的模拟JPEG测试通过：默认关闭、开启/关闭、单请求、帧率限制、另一查看者占用、错误接口、过期/重复/损坏帧、超时和后台关闭。模拟测试不是真实摄像头图传测试。

尚未替用户烧录，也未确认实物成功出图；待检查PSRAM、排线、安装方向、电源稳定性，以及视频与体感控制同时运行时的延迟。
