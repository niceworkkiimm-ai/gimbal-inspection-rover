# V8.6 手持三模式与摇杆接线

日期：2026-09-14。手持NodeMCU程序V1.3。只重新烧录手持端；STM32 V8.2、基座ESP V4.8、摄像头V1.2及2D/3D网页V8.5不需要更新。

## 使用方式

短按摇杆并松开，依次切换：

**体感云台 → 体感小车 → 摇杆小车 → 体感云台**

- 体感云台：继续用MPU6050倾斜控制云台。
- 体感小车：继续用MPU6050倾斜控制前后行驶和左右转向。
- 摇杆小车：Y轴控制前进/后退，X轴控制左右转向，松手回中停车；不是左右平移。
- 长按摇杆0.8秒：请求软件停车。松开不会恢复，再短按返回体感云台。
- 上电默认体感云台；断网回到体感云台，重连后不会自动恢复行驶。
- 切换时按下会暂停有效控制。切入小车模式先让对应输入回中，STM32原有回中检查仍生效。
- 摇杆模式独立读取ADS，不叠加MPU姿态，也不在此模式进行MPU重新校准。
- OLED显示三个本地请求模式；摇杆模式的X/Y是推杆百分比，不是姿态角、车速或基座执行反馈。
- 基座屏幕和网页仍把两种驾驶输入统称“小车模式”；本次没有更改基座/STM32/网页协议。

## 完整手持端接线

本表适用于支持3.3V的普通双电位器摇杆（X、Y模拟输出，SW按下接地）和普通ADS1115模块。若购买的是5V专用、带放大/比较电路的不同模块，先核对资料，不直接照接。

| 部件 / 引脚 | 接到哪里 |
| --- | --- |
| NodeMCU板载USB | 电脑USB数据线，用于Arduino烧录，也可供电 |
| 不用USB时：稳定5V正极 | NodeMCU VIN |
| 不用USB时：5V电源负极 | NodeMCU GND |
| NodeMCU EN、RST | 保持板载电路，不需要外接 |
| NodeMCU GPIO0、GPIO2 | 正常运行不接地；本方案不占用 |
| MPU6050 VCC | NodeMCU 3V3 |
| MPU6050 GND | NodeMCU GND |
| MPU6050 SCL | NodeMCU D1 / GPIO5 |
| MPU6050 SDA | NodeMCU D2 / GPIO4 |
| MPU6050 AD0 | GND，地址0x68 |
| MPU6050 INT、XDA、XCL | 不接 |
| SSD1306 128×64 I²C OLED VCC | NodeMCU 3V3，屏幕须支持3.3V |
| OLED GND | NodeMCU GND |
| OLED SCL | D1 / GPIO5，与MPU的SCL并联 |
| OLED SDA | D2 / GPIO4，与MPU的SDA并联 |
| ADS1115 VDD / VCC | NodeMCU 3V3 |
| ADS1115 GND | NodeMCU GND |
| ADS1115 SCL | D1 / GPIO5，与MPU/OLED的SCL并联 |
| ADS1115 SDA | D2 / GPIO4，与MPU/OLED的SDA并联 |
| ADS1115 ADDR | GND，固定地址0x48 |
| ADS1115 A0 / AIN0 | 摇杆X / VRx |
| ADS1115 A1 / AIN1 | 摇杆Y / VRy |
| ADS1115 A2、A3 | 不接 |
| ADS1115 ALERT / RDY | 不接，本程序轮询转换状态 |
| 摇杆 VCC | NodeMCU 3V3 |
| 摇杆 GND | NodeMCU GND |
| 摇杆 SW / KEY | NodeMCU D5 / GPIO14，按下接地，内部上拉 |
| 原独立按键 | 拆除，由摇杆按下功能接替 |
| NodeMCU A0 | 本方案不接；摇杆X/Y接的是ADS1115的A0/A1 |

注意：USB供电与外部VIN供电二选一，不同时接。5V只送NodeMCU的VIN/USB输入，不能送3V3、SDA、SCL、SW或ADS模拟输入。所有模块共地，I²C上拉只能到3.3V。ADS量程设为±4.096V只是转换比例，3.3V供电时不代表允许输入4V或5V。

MPU地址0x68、OLED地址0x3C/0x3D、ADS地址0x48互不冲突，共用D1/D2即可，不用换更多引脚的开发板。但总线被短路会同时影响多个设备，软件不能隔离物理短路。

## 第一次测试

1. 四轮架空、车架固定，手边能立即切断电机电源。软件长按停车不代替断电。
2. 上电后手持平放，摇杆不动且松开约2秒；先让MPU和摇杆中点完成校准。
3. 短按一次，OLED应显示“体感小车”；再短按一次显示“摇杆小车”；再一次回到“体感云台”。
4. 摇杆模式先放开回中，等待就绪；分别测试小幅前推、后拉、左推、右推。暂不落地全速运行。
5. 默认X电压增大对应右转，Y电压增大对应前进。实物安装方向不能从“X/Y输出”文字确定，必须验证。
6. 若前后反了，只把 **HandheldInputConfig.h** 中 **kYSign = 1** 改成 **-1**；左右反了只改 **kXSign**。重新烧录手持端即可。
7. 若物理前后推动改变的是串口X值而非Y值，则X/Y轴对应不一致：断电核对VRx/VRy接线和安装方向，再决定交换ADS A0/A1，不能只靠改符号修正轴交换。
8. 松手应停车；按住0.8秒应进入“停车请求”，松开不能自行恢复。
9. 确认三个模式均正常后再进行低速落地测试。

串口摇杆日志例：
`MODE=JOYSTICK READY=1 X=0 Y=0 ADC=13200,13200 CAL=1 ERR=0`

这里数值仅为示例：±4.096V量程下每计数125µV，3.3V供电时中点常在13200附近，并不是固定必须等于13200。

- CAL=0：中点未校准。先松开摇杆，查供电/接线；中点必须在合理电压范围内并持续稳定。
- ERR增长 / OLED摇杆未就绪：ADS地址、电源、I²C或转换数据异常；不要带故障驾驶。
- 请松手回中：切换或错误恢复后的回中确认未满足。
- X/Y持续±100：先检查摇杆是否真的推到底，排查模拟线短路/接错；不是软件能保证识别的故障。
- 普通电位器断线后可能浮到一个看起来合法的电压，不能宣称本方案能检测所有断线。发现不符预期立即断电检查。

## 实现与验证范围

手持端本地区分模式0体感云台、1体感车、3摇杆车、2停车。无线仍使用原H1协议：模式3映射为车模式1，每次切换epoch递增。基座和STM32已有逻辑会按新的epoch停止并重新检查回中，不需要修改接收端。

ADS配置按TI ADS1115 SBAS444E（2024-12）核对：地址0x48，A0/A1对GND单端采样，PGA±4.096V，860SPS单次转换。A0配置0xC3E3，A1配置0xD3E3。两轴轮流读取，不是同时采样；不等待转换忙循环。每个完整采样对的启动目标间隔20ms，只在原20ms控制发送周期空隙做有界I²C操作。100ms内的新完整采样对才可用，转换超时/配置错误使输入无效。

摇杆中点在合理范围内稳定后学习一次，8%中心死区；不在行驶中不断重学中心。ADC出错后保留已学习中点，但必须回中再允许控制。有效输入映射为原车控角度范围，保留STM32的30% PWM上限、回中确认、缓启动、换向停顿和失联保护。其“角度值”在摇杆模式下是兼容控制指令，不是MPU实际姿态。

电脑验证已完成：

- Arduino ESP8266 3.1.2 / NodeMCU编译通过，无新增库。
- 原MPU读取、卡尔曼滤波、校准算法和H1协议文件保持不变；STM32执行代码保持不变。
- 原OLED与体感功能回归通过；新增三种模式中文和摇杆状态已渲染检查，文字完整。
- 真实手持代码配合模拟I²C/UDP测试：三模式、短抖动、长按停车、模式序号回绕、回中、ADC缺失/忙超时/配置错误/过期数据、MPU失效时摇杆独立运行、Wi-Fi断开与重连通过。
- 实际CarLogic代码验证虚拟输入的前进/后退/左右原地转向、回中停车及30%上限。
- 主机模拟普通控制发送约20ms周期；模式切换因是否读取MPU会产生一次小于23ms的间隔变化。不是实机端到端延迟测量。

实物待验证：摇杆供电规格/方向、中点偏差、按键电平、I²C线长与上拉、三模式车辆动作。未替用户自动烧录。缓存和测试位于D盘，不需要把缓存复制进工程。
