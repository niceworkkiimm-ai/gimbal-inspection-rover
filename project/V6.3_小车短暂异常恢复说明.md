# V6.3 小车短暂异常恢复

更新日期：2026-09-08。修改的是“新版嵌入式”中的本工程，旧工程不改。

本次需要烧录 **STM32 和手持 NodeMCU 两个设备**；基座 ESP-01S 不需要烧录，网页和全部接线不变。

## 这次解决什么

旧版遇到一次无效姿态或过大倾斜，就取消小车的控制就绪状态。即使后续数据恢复，继续倾斜手持端也不能开车，必须放平，因而会长时间显示 CAR:LEVEL。

V6.3 对已经正常控制中的小车增加短时恢复：

- 短暂无效输入或过倾，立即将四路 PWM 归零，不沿用旧速度。
- 从首次异常开始的 300 毫秒内，收到至少 3 个新的有效包，稳定至少 40 毫秒，且校正后两个角度都在 ±50 度以内，自动从零渐变恢复。
- 重复读取同一个数据包不算新数据；反复异常不能延长这 300 毫秒窗口。
- 恢复时保持原来的 PWM 缓升和换向停顿，不直接跳回异常前的占空比。
- 上电首次进入小车、切换模式、超过 250 毫秒失联、持续异常仍要求回中；串口或主循环故障仍保留停车保护。

这是减少短暂干扰导致的反复回中，不是取消所有停车保护，也不保证供电或传感器存在持续故障时仍能行驶。

## 手持端 V1.1

- 按键电平持续稳定 35 毫秒后才确认按下/松开，短毛刺不再清除姿态有效标志。
- 单次 MPU6050 读取失败仍发送无效数据让车暂停，但不立刻进行整套初始化和校准。
- 连续 3 次读取失败才进入重新初始化；中间一次成功会清零失败计数。
- 原有 100 毫秒健康数据确认、短按切换、长按 0.8 秒软件停车不变。

## 烧录哪个文件

1. STM32：打开本目录的 `Gimbal_STLink.uvprojx`，选择 `Gimbal STLink`，执行 `Rebuild` 和 `Download`。
2. 手持：打开 `NodeMCU_Handheld_MPU_Car/NodeMCU_Handheld_MPU_Car.ino`，Arduino 的 `Board` 选择 `NodeMCU 1.0 (ESP-12E Module)`，`Port` 选手持端，点击 `Upload`。这是 NodeMCU V3 的程序，不要烧旧的 `ESP01S_Handheld_MPU_UDP`。
3. 基座 `ESP01S_Base_UDP` 不动；H1 和车辆遥测协议不变。

STM32 与手持端均已编译通过，尚未自动烧录。手持串口启动日志为 `HANDHELD V1.1`。

## 接线和参数

本次没有引脚变化；完整接线已同步保留在 `User/main.c` 开头。

- 手持 MPU6050：VCC→3V3、GND→GND、SDA→D2/GPIO4、SCL→D1/GPIO5、AD0→GND；按键→D5/GPIO14 与 GND。用板载 USB 烧录/供电。
- PD3 仍不接，没有新增硬件锁。
- 最大 PWM 仍为 30%；Pitch 控制前后，Roll 控制原地左/右转；右侧 2/4 轮反相保持不变。
- 停止/回中范围仍为屏幕原始 ROLL −8～8 度、PITCH −10～6 度，持续约 0.4 秒并收到至少 10 个新包。

## 屏幕提示与试用

| 提示 | 含义 |
| --- | --- |
| CAR:CHECK | 短暂异常后正在确认新数据，PWM 为 0；确认通过后可自动恢复 |
| CAR:INPUT | 手持姿态无效；稳定手持、松开按键，检查 MPU 和接线 |
| CAR:TILT | 倾斜过大，或恢复阶段尚未减小到允许范围 |
| CAR:LEVEL | 仍需要放平约半秒，例如刚切到小车模式或持续异常后 |
| CAR:LOST | 小车输入已超过 250 毫秒没有更新 |
| CAR:FAULT | 故障停车；排查后退出小车模式再进入 |
| CAR:READY / RUN | 已就绪 / 正在输出 PWM |

TFT 按原有周期刷新，很短的 CHECK/INPUT 不一定能肉眼看到。基座网页沿用原状态码，短时检查可能仍显示原有“请放平”提示，以实际恢复行为和 TFT 为准。

烧录后先保持四轮架空、车架固定并能随时断开电机电源，手持上电时水平静止完成校准。短按进入小车模式，放平到 READY 后分别前后、左右倾斜试转，再持续操作几分钟观察是否还频繁 LEVEL。真实断联恢复后仍需放平，这是保留的行为。

若仍长时间 INPUT/LEVEL，请记录屏幕状态和手持串口日志；本次源码修改不能证明实际 Wi-Fi、供电和 MPU 已无故障。
